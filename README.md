# Smart Counter Island

> 教室大屏（希沃等 Windows 10/11 一体机）上的 iOS 灵动岛风格倒数日悬浮窗：高考 / 中考 / 期末考倒计时常驻屏幕顶端，带 liquid glass 质感、全屏授课自动隐藏、系统通知接管与上课时间表。

**零运行时依赖 · 零原生模块 · 免安装运行库 · x64 单文件分发**

- 安装包 71.4 MB / 便携版 71.2 MB（v3.0.0 构建实测；内置 Electron 运行时，目标机器无需装 Node）
- 首帧显示约 0.4–0.5 秒；细条静止态约 16% 单核占用（开发机实测，默认设置）
- 273 项自动化断言覆盖状态机、玻璃管线（含 GPU 链路与帧率）、通知、时间表、定时任务、天气（映射/解析/文案/去重/离线降级/细条常驻几何）、壁纸生成、屏幕挖孔避让、桌宠移动与配置页

## 快速上手

1. 从 [Releases](https://github.com/SenbonFanKageyoshi/smart-counter-island/releases) 下载：
   - `SmartCounterIsland-Setup-<版本>.exe` —— 安装版（开始菜单/桌面快捷方式，可改安装目录）
   - `SmartCounterIsland-<版本>-portable.exe` —— 便携版（免安装，双击即用）
2. 程序未做代码签名，Windows 可能提示「未知发布者」→「更多信息 → 仍要运行」。
3. 首次运行：**双击托盘图标**打开配置 → 「倒计时事件」→ 添加（名称 / 目标时间 / 图标 / 颜色 / 启用）。
4. 换机器/换屏后如果不在预期位置：配置页「显示效果 → 窗口位置」里三种形态可各自设置位置与所在显示器。

## 显示逻辑

### 时间单位自动降级（三种形态通用）

主时间单位从「天」开始逐级下降，取第一个**够一个单位**的：不足 1 天 → 时，不足 1 小时 → 分，不足 1 分钟 → 秒。

| 剩余时间 | 灵动岛 | 横幅 | 倒计时窗口 |
|---|---|---|---|
| 2 天 5 小时 | `2 天` | `距 期末考 还有 2 天` `05:20:30` | 主行 `2 天` / 副行 `05时20分30秒` |
| 3 小时 20 分 | `3 时` | `距 期末考 还有 3 时` `20分30秒` | 主行 `3 时` / 副行 `20分30秒` |
| 20 分 | `20 分` | `… 20 分` `30秒` | 主行 `20 分` / 副行 `30秒` |
| 45 秒 | `45 秒` | `… 45 秒` | 主行 `45 秒`（无副行） |

配套设置「**灵动岛日期估算方式**」决定天数的取整：

- **向上取整** —— 不足一天算一天（剩 3 小时显示 `1 天`）
- **四舍五入** —— 满半天算一天
- **向下取整**（默认）—— 不足一天不算，交给单位降级显示 `3 时`

### 什么时候是什么形态（状态机）

| 条件 | 结果 |
|---|---|
| 用户有键鼠/触摸操作 | 灵动岛（并进入 60 秒大屏冷却，避免收起后又立刻弹出） |
| 闲置 ≥ `闲置多少秒后展开横幅`（默认 4s） | 横幅 |
| 横幅已展开 ≥ `横幅展开后再闲置多少秒弹出大屏`（默认 15s，0 = 不自动） | 倒计时窗口 |
| 前台窗口全屏（盖住任务栏，授课/视频/演示） | 按「**全屏授课时**」设置：彻底隐藏（默认）/ 右上角角落卡片 / 屏幕顶部进度条 / 保持灵动岛小条；全部**鼠标穿透**，退出全屏自动恢复。判定标准是前台窗口盖住任务栏区域，**窗口最大化不算** |
| 前台窗口最大化 | 收成灵动岛（可关） |
| 有计时事件但全屏中 | 按上面的设置形态显示 + 鼠标穿透，不响应任何手势 |
| 光标停在小岛附近 | 不自动展开（悬停保护范围可调） |
| 没有启用中的事件 | 空态提示 / 纯黑小条 |

**手动模式（托盘右键菜单 / 配置页「智能行为 → 手动模式」）**：

| 模式 | 行为 |
|---|---|
| 自动（默认） | 完全按上表的状态机跑 |
| 固定显示 | 始终可见（不因闲置/最大化收成灵动岛） |
| **大窗口驻留** | **倒计时窗口常显**：不因闲置、鼠标操作、悬停或冷却期收回，适合整天挂在教室大屏上展示；全屏遮挡或无有效事件时仍回到灵动岛（不遮挡授课） |
| 隐藏成灵动岛 | 始终细条，鼠标悬浮也不展开 |

### 玻璃效果（5 种 + 灵动岛样式）

| 模式 | 说明 |
|---|---|
| **液态玻璃**（默认推荐） | 中心区域**逐像素与桌面原画一致**，只有边缘一圈窄折射带做光学弯曲；浅灰 1px 边线 + 顶部高光带 + 下部渐暗（玻璃厚度感）。折射带宽/位移/渗色/高光全部**按窗口高度自适应**。走「截屏 → 位图 → SVG 滤镜」链路 |
| **液态玻璃（GPU 加速）** | 同样的观感，但改为**屏幕视频流 + WebGL 着色器**（刷新帧率可调 1–60，见「GPU 玻璃帧率」）：主进程不再截屏、不再做 PNG 编码与数据回传，折射/渗色/高光在 GPU 上一次着色完成。开销与取舍见「性能」；取流失败或页面布局异常时自动回退到上一条 |
| **真实模糊** | 截屏后做高斯模糊的毛玻璃（观感最"厚"，开销略高） |
| **模拟玻璃** | 纯 CSS 渐变 + 噪点，不截屏（低配机器或截屏受限时用） |
| **关闭** | 纯黑底白字 |

- 「**灵动岛样式**」单独可选：黑底白字 / 跟随玻璃效果（后者让顶部小条也变成玻璃质感，文字随背景明暗自适应）。
- 文字对比度：亮背景用深色字 + 浅色描边，暗背景用白字 + 深色描边；黑底形态（灵动岛黑底 / 通知弹窗 / 关闭玻璃）恒为白字。
- 玻璃在**窗口尺寸动画期间**会暂时隐藏（避免缩放中露出方形模糊边），动画结束立刻恢复。

#### 玻璃观感调参位置

| 参数 | 位置 | 默认 |
|---|---|---|
| 折射带宽 / 最大位移 | `liquid-glass.js` / `glass-webgl.js` 的 `band` / `maxD` | 高度的 20% / 7%（自适应） |
| 边缘渗色宽度 / 浓度 | 同上 `bleed` / `bleedOpacity` | 高度 15%（3–10px）/ 0.7 |
| 边缘高光宽度 / 强度 / 顶部增量 | 同上 `glow` / `spec` / `topBoost` | 高度 10%（1.5–8px）/ 0.72 / 0.5 |
| 底部渐暗强度 | 同上 `bottomShade` | 0.2 |
| 顶部高光带、两端弧线、下部渐暗 | `island.css` 的 `body[data-glass="liquid"] .glass-tint` | 只影响「表面光影」，与折射无关 |

配置页「显示效果 → 玻璃高光强度」是两条链路共用的高光总开关；「高级 → GPU 液态玻璃观感」四项只缩放 GPU 着色器的 `spec`+`topBoost` / `bottomShade` / `maxD` / `band`（100% = 上表默认值）。

## 天气

配置页「天气」标签：城市填一次（自动地理编码成经纬度并缓存），之后按刷新间隔自动更新；提醒规则独立成表，到点走通知弹窗（雨雪时整条灵动岛播特效）。

| 项 | 说明 |
|---|---|
| 数据源 | Open-Meteo（免密钥、零配置）：地理编码 + 当前天气 + 逐小时 + 7 天预报，`timezone=auto` |
| 城市 | 手填城市名 → 「解析城市」确认「城市 · 省/州 · 国家」；「自动定位」按公网 IP 一键填（仅点击时执行） |
| 刷新 | 默认 30 分钟（最小 10）；断网/超时 8 秒后保留旧数据并标注「数据已过期」，重试退避到 3 倍间隔 |
| 岛内显示 | **常驻**：细条（紧凑 chip，只图标+温度）/ 横幅 / 大卡片都显示；挖孔屏下细条自动加宽出天气槽，两瓣仍紧贴禁区。可选「仅横幅·大卡片」或「不显示（只用提醒）」 |
| 天气位置 | 细条上放哪儿：**右端**（默认）/ **左端** / **盖板上**（画在中那块传感器盖板窗口里，细条不占位；会与摄像头区域重叠，摄像头不参与使用时再选） |
| 盖板自定义内容 | 中间盖板上还能画**自定义文字**：模板 + 程序变量（`{name}` `{days}{unit}` `{time}` `{temp}°` `{weather}` `{next}` `{min}` `{subject}` `{week}` `{count}` …共 16 个），配置页可点变量胶囊插入 + 实时预览（按当前真实数据渲染）。写了文字就不再自动画天气 chip（想要天气就写 `{temp}° {weather}`）—— 盖板宽度就等于禁区宽度，太长会省略号截断 |
| 天气动画 | 图标动画：晴（光线旋转）/ 多云（云飘）/ 阴 / 雨（雨丝）/ 雪（雪花）/ 雷（闪）/ 雾（流动）；强度 0–200（0 = 静止），尊重系统「减少动效」 |
| 提醒特效 | 天气提醒弹出时整条岛按天气播雨丝/雪花/晴空/云影/雷闪/雾带（层数按强度缩放） |
| 指定时间提醒 | 独立规则表：`时间 + 星期（每天/仅一次/工作日）+ 内容`；内容类型：当前天气 / 今日概况 / 明日预报 / 降雨提醒（未来 N 小时）/ 降温·高温提醒（阈值可调） |
| 提醒去重 | 与定时任务同语义：20 秒轮询匹配到分钟，同一分钟不重复；「仅一次」触发后自删 |
| 关键词高亮 | 正文中的「雨/雪/大风/降温/高温」红色高亮（可自定义） |
| 「试一条」 | 配置页一键按所选类型弹示例，确认文案与动画效果 |

> 首次使用：配置页「天气」→ 勾选启用 → 填城市 → 点「解析城市」确认 → 点「立即刷新」看状态行 → 加一条「每天 07:00 今日概况」。

## 配置项一览

配置窗口分 10 个标签页（`托盘双击` 或右键 → 打开配置）。以下为全部可调项与默认值。

事件列表 + 「＋ 添加事件」。每个事件包含名称、目标时间（到分钟）、图标 emoji、强调色、启用开关；列表项上可**置顶**（固定显示该事件，多事件时优先生效）、启用/停用、编辑、删除。

### 时间表

一节一条记录：**节次自动编号** + 开始/结束时间 + **科目**（可留空，填了提醒里就会说「第 3 节 数学」）。

| 配置项 | 说明 |
|---|---|
| 启用时间表 | 总开关（关掉后课堂提醒、免打扰都退回默认行为） |
| 几周一休 | `0` = 每周相同，`2` = 单双周（休息周可少排课） |
| 快速排课 | 「第 1 节开始时间 + 每节时长 + 课间时长 + 节数」一键生成到第 1 周（默认只填工作日），不用一节一节手填 |
| 导出 / 导入 | 整份时间表导出成 JSON 复制给别人；粘贴别人的 JSON 点导入即可（老师之间共享课表） |
| 复制此天 / 复制此周 / 复制到所有周 | 两次点击完成：点「复制」→ 点目标天/周 |
| 预览行 | 实时显示「现在 10:02 · 正在上：第 2 节 数学（9:55–10:40）· 下一节：第 3 节 英语 10:50（8 分钟后）」 |

支持**跨午休**时段（如 23:30–00:01，下课提醒会在次日凌晨正确触发）。课表解析统一在 `src/main/schedule.js`，免打扰与课堂提醒共用同一套逻辑。

### 课堂提醒（时间表驱动）

勾上时间表就会自动提醒，**不需要一条条配任务**。

| 触发点 | 默认 | 说明 |
|---|---|---|
| 课前提醒 | 3 分钟前 | 「还有 3 分钟上课 · 第 3 节 数学」 |
| 上课提醒 | 开 | 「上课时间到 · 第 3 节 数学」 |
| 下课前提醒 | 2 分钟前 | 「还有 2 分钟下课」 |
| 下课提醒 | 开 | 「下课时间到」 |

- 文案可自定义，占位符：`{min}` 分钟数、`{n}` 节次、`{subject}` 科目、`{label}` 节次+科目、`{time}` 时刻。
- **同一天同一节同一触发点只提醒一次**（不会因为 20 秒轮询重复弹）。
- 课堂提醒属于教学刚需，**不受系统通知的免打扰影响**；「免打扰至下课」只用来抑制别人发来的系统通知。
- 检查频率 20 秒，匹配到分钟即可。

| 类型 | 说明 |
|---|---|

| 定时关机 | 支持「关机前 N 分钟提醒」，弹窗带「取消关机」按钮；取消后**当天不再触发** |

### 桌宠（教学助手）

独立透明「舞台窗口」里的一只桌宠：课间陪学生互动、上课/下课提醒出面播报、答疑（可选接 AI）。

| 配置项 | 默认 | 说明 |
|---|---|---|
| 启用桌宠 | 关 | 总开关（默认关，老师自己开） |
| 大小 / 走动速度 / 透明度 | 100% / 100% / 95% | |
| 全屏授课时隐藏 | 开 | 与灵动岛同一套全屏判定，不遮挡授课 |
| 上课时间静默 | 开 | 上课时站着不动、不闲聊，只答课表与倒计时 |
| 上课/下课提醒时桌宠也念一句 | 开 | 课堂提醒 = 通知弹窗 + 桌宠播报 |
| 预置问答 | 关 | 一行一条「关键词 \| 回答」，离线也能答，零成本零风险 |

**答疑（AI）**：OpenAI 兼容接口，服务商/模型/Key 都可填（DeepSeek、通义、智谱、豆包…）。

- **永不开启思考模式**：请求体固定带 `thinking:{type:'disabled'}`；模型名带 `reasoner/thinking/r1/o1/o3` 会被强制改回 `deepseek-chat` 并在配置页提示。实测：关掉思考首字 551ms / 整段 834ms / 输出 12–30 tokens；开启思考则 1366ms / 1519ms / 最多 1389 tokens。
- **配额与缓存**：每分钟 / 每天提问上限（默认 6 / 200）；同一个问题 10 分钟内复用答案。
- **断网降级**：未配 Key、断网、超配额 → 自动用预置问答，并在气泡里说明原因（离线不会变成哑巴）。
- **护栏**：回答长度上限（默认 120 字，超出截断）、敏感词拦截、自动去掉 Markdown/代码块。
- **课堂纪律**：上课时间拒绝闲聊（只答课表/倒计时）；免打扰期间不主动说话。
- 状态行显示模型、是否配置 Key、预置条数、提问次数（AI/预置/拒绝）与平均首字延迟，另有「连接自检」「让它说一句」两个按钮。

> 两个窗口互不影响；桌宠同样做了 `WDA_EXCLUDEFROMCAPTURE`，不会被小岛的玻璃拍成重影。
> 移动方式：桌宠在舞台窗口内自由走动（60fps），只有走到舞台边缘才整窗平移一次 —— 实测逐帧移动窗口只能跑到 21–32 次/秒且会占住主进程，舞台方案把它降到约 1 次/秒。

#### 桌宠素材包（形象）

程序自带占位小人（几何图形）；想要自己的形象就做一个素材包目录：`pet.json` + 图片。

| 状态 | 用途 |
|---|---|
| `idle` | 发呆/待机（**必须提供**） |
| `walk` | 走动（左右自动镜像，只画一个朝向即可） |
| `sleep` | 久无人互动时睡觉 |
| `talk` | 说话中 |
| `quiet` | 上课静默站立（可省，省了用 `idle`） |

三种写法可混用（路径都相对素材包目录）：

```jsonc
{
  "name": "我们班的小岛",
  "scale": 100,        // 默认大小 %
  "anchorY": 0,        // 脚底相对图片底部的偏移（px，正数往上抬）
  "fps": 4,            // 各状态没单独设 fps 时的默认值
  "states": {
    // ① 帧序列：一帧一个文件（最直观）
    "idle":  { "fps": 4,  "frames": ["idle_1.png", "idle_2.png", "idle_3.png"] },
    // ② 精灵图：一张长图切 N 格（最省文件，推荐；从左到右、从上到下切）
    "walk":  { "fps": 10, "sheet": "walk.png", "frames": 6, "cols": 6 },
    // ③ 动图：GIF / 动态 WebP，浏览器自己播
    "sleep": { "file": "sleep.webp", "fps": 12 }
  }
}
```

- 支持 `png / jpg / webp / gif / bmp / svg`，单文件上限 3MB；建议透明背景 PNG（或带 alpha 的 WebP）。
- 尺寸建议：像素风 32×32 或 48×48 一帧；插画风 96×96–160×160。帧数 idle 2–4、walk 4–8、talk 2–4、sleep 2 就够。
- 「配置 → 桌宠 → 素材包」：打开文件夹 / 浏览 / **生成示例素材包** / 重新加载。默认目录 `%APPDATA%\SmartCounterIsland\pets\示例`，生成的目录里自带 `素材包说明.txt`。清单坏了或图片缺了会自动退回内置占位小人，不会白屏。

## 性能

> 数据在本机（远程会话，DXGI 抓屏异常）实测，量级与比例可参考；绝对值在真机上通常更优。

### CPU 花在哪（20 秒累计 CPU 秒，按进程角色）

| 场景 | 主进程 | GPU 进程 | 渲染进程 | PowerShell 探针 |
|---|---|---|---|---|
| 横幅 · 玻璃常显 · 刷新 0.5s | 4.30 | 0.73 | 0.25 | 0.98 |
| 细条 · 静止 · 刷新 1.6s | 2.44 | 1.06 | 0.39 | 1.16 |

- **渲染/合成/滤镜/动画几乎不吃 CPU**：窗口合成、CSS 模糊、液态玻璃的 SVG 滤镜链都跑在 GPU 光栅化上（渲染进程仅 1–2%）。
- **大头是主进程的截屏管线**：`desktopCapturer.getSources()` 单次耗时占该管线 98% 以上（整屏 DXGI 抓取 + 缩放进 CPU 内存），其后处理很便宜（位图指纹 1.7 ms、PNG 编码 4 ms、IPC 约 16 KB/帧）。已做的优化：只在需要玻璃时抓整屏 1:1 图，其余情形只抓 480px 小图算亮度（数据量 8 MB → 约 0.5 MB）；背景未变化时跳过编码与传输。
- **探针是常驻 PowerShell 子进程**，纯 CPU（约 5–6% 单核），已按活跃度分档采样（活跃 350ms / 常规 700ms / 全屏隐藏或关闭通知时 1050ms 且跳过通知枚举），窗口枚举已下推到编译过的 C#。

### 影响能耗的三个设置（按收益排序）

1. **背景刷新间隔**：`0.5s` 相对 `1.6s` 多花约 2.9 秒 CPU/20 秒（约 +8% 单核）。玻璃只在窗口尺寸或背景变化时才需要新图，建议 **1.0–1.6 秒**。
2. **玻璃效果**：低配机器用「模拟玻璃」或「关闭」可直接省掉整条截屏管线。
3. **动画帧率**：60 足够；20–30 可进一步降耗（动画时长固定 150 ms，低帧率表现为掉帧而非变慢）。

### 其它实测

| 指标 | 数值 |
|---|---|
| 首帧显示（进程启动 → 窗口可见） | 约 0.42–0.55 秒 |
| 状态切换动画实际时长 | 141–166 ms（设定 150 ms） |
| 私有内存 / 工作集（4 进程合计） | 约 230–260 MB / 375–400 MB |
| 解压后目录 / 安装包 / 便携版 | 229 MB / 71.4 MB / 71.2 MB |

### GPU 现状

Chromium 侧 `gpu_compositing` / `rasterization` / `canvas_oop_rasterization` / `webgl` 均为 **enabled**，实测渲染后端为 `ANGLE (Direct3D11)`。**GPU 加速已经在用**：窗口合成、动画、CSS 模糊，以及液态玻璃的折射/渗色/高光都在 GPU 上完成。

### GPU 液态玻璃（屏幕视频流 + WebGL）的实测取舍

「液态玻璃（GPU 加速）」把原来的「整屏截屏 → CPU 位图 → PNG 编码 → IPC → CSS/SVG 滤镜」换成「屏幕视频流（GPU 帧）→ 裁出小岛附近一小块 → 纹理 → WebGL 着色器一次着色」。同一台机器、同一场景（横幅 · 玻璃常显 · 20 秒）：

| 配置 | 主进程 | GPU 进程 | 渲染进程 | 探针 | 合计 CPU |
|---|---|---|---|---|---|
| **CPU 液态玻璃（兼容模式）** | 2.31 s | 0.81 s | 0.31 s | 0.89 s | **17.6% 单核** |
| GPU 模式 · 帧率 2fps | 0.78 s | 1.59 s | 0.27 s | 1.00 s | **13.9% 单核** |
| GPU 模式 · 帧率 15fps | 2.16 s | 1.77 s | 0.69 s | 0.84 s | **23.3% 单核** |
| GPU 模式 · 帧率 45fps | 3.75 s | 1.67 s | 1.44 s | 0.97 s | **34.7% 单核** |

- **帧率就是"实时感"的价钱**：2fps 比 CPU 兼容模式还便宜（玻璃跳变式更新），15fps 观感已经连续，45fps 基本跟手但 CPU 是兼容模式的两倍。
- 主进程开销随帧率线性上升 —— 这是**透明窗口逐帧更新的固有成本**（Chromium 侧合成协调），与着色器无关；独立 demo 里"只显示视频流、不做任何着色"的实时镜像同样要 ~20% 单核。
- GPU 进程的开销主要来自屏幕采集服务（DXGI 复制/转换），它随帧率上升；这也是任何屏幕捕获方案（包括 WGC 原生模块）都省不掉的固定成本。
- 上传只裁窗口附近一小块（约 0.15 MB/帧，是整帧 1920×1080 的 1/50），因此渲染进程随帧率的增长很平缓。

> 上表在开发机（远程会话，DXGI 抓屏受限，实际取流只有约 6–11fps）测得：所以 15/45fps 两档的真实开销会比表中略高（取流供不上时会被动降级）。其中 GPU 模式**取流失败或页面布局异常会自动回退** CPU 兼容模式，不改用户设置、仅本次运行生效。
> 另有一个独立的最小验证工程 `glass-live-demo`（与主项目同级的目录，不在本仓库内）：透明窗口 + 屏幕视频流，三种模式（实时镜像 / 边缘折射 / 整片透镜）可现场对比，并用 `bench.ps1` 输出「流帧率 + 按角色拆分的 CPU」。它用于测量"纯实时"的上下限：1080p 下实时镜像约 55fps / 77% 单核，逐帧边缘折射 45fps / 111% 单核。

                       │ IPC（状态 / 事件 / 通知 / 玻璃图 / 亮度）
┌──────────────────────┴─────────────────────────────────┐
│ 渲染进程 (src/renderer/island)                          │
│   island.js        四态渲染 · 每秒文本更新 · 手势       │

│   glass-webgl.js   屏幕视频流 + WebGL 着色器（GPU）     │
│   island.css       形态 / 玻璃 / 文字对比度样式         │

        ↕ stdin "probe" → stdout JSON
┌────────┴───────────────────────────────────────────────┐
│ 常驻 PowerShell 探针 win-probe.ps1                     │
│   -Sta · Win32 P/Invoke + UI Automation                │

- **液态玻璃管线（CPU 链路）**：按窗口几何生成圆角矩形 SDF → 用向外法线做**反向采样位移**（内容向外推，形成凸透镜边缘弯曲）→ 三次方衰减保证中心位移为 0（中心与原画逐像素一致）→ 叠加边缘渗色与镜面高光；贴图按 `devicePixelRatio` 生成以避免边缘马赛克，`feDisplacementMap` 的 scale 与位移图编码严格一致。
- **液态玻璃管线（GPU 链路，可选模式）**：主进程注册 `setDisplayMediaRequestHandler` 指定「小岛所在显示器」为视频源；渲染层 `getDisplayMedia()` 取流 → `drawImage` 把「小岛附近一小块」裁到小 canvas（约 0.15 MB/帧）→ 上传纹理 → 同一套 SDF 数学改写成 GLSL 片元着色器（折射 + 6 抽样渗色 + 镜面高光 + 下部渐暗）一次着色完成；帧率压到 2fps，不需要玻璃时暂停视频并停用轨道；取流/着色器/几何任一失败都会**自动回退**到 CPU 链路（不改用户设置，仅本次运行生效）。
- **截屏排除自身**：主进程调用 `setContentProtection`（即 `WDA_EXCLUDEFROMCAPTURE`），一次设置持续生效 —— 截到的是窗口背后的真实像素，无重影，**无需每次截屏隐藏窗口**（因此不会闪烁）。副作用：本窗口在你自己的录屏/截图里也不可见。
- **圆角与 DPI**：`SetWindowRgn(CreateRoundRectRgn)` 做圆角命中区域（物理像素、外扩 3px 藏住 Win32 锯齿边）；窗口尺寸按显示器 DIP 计算，玻璃图用物理像素 1:1 抓取并按 `offX/offY` 对齐，窗口贴屏幕边缘时不会错位。
- **传感器避让**：传感器（挖孔摄像头）用「相对屏幕水平中心偏移 / 距顶 / 直径」记录，**坐标永不改变**；禁区 = 传感器并集 + 空隙（或手动矩形）。小岛负责把镜头裹住：**黑底顶边跟着禁区**（最多上移到贴着屏幕顶），细条**左右分栏**，横幅与大卡片**长到传感器下方**（黑底高度 = 禁区深度 + 原内容高度）。那块黑由**独立的「传感器盖板」窗口**兜底：纯黑胶囊（`border-radius = 窗口高/2`，贴屏幕边的部分裁掉）、**创建即显示**、`screen-saver` 置顶（随小岛的每 tick 置顶断言一起抢层并补齐显示）、鼠标穿透、`setContentProtection` 不参与截屏；位置与大小只由禁区决定，**永不移动、永不缩放**，小岛收缩 / 自动隐藏 / 全屏授课时它都还在；盖板落在小岛黑底**内部**，两块黑看上去是一整块。内容按两种布局让位——`split` 左槽 `anchor left + 14px`、右槽 `anchor right + 12px`（中间 `[zoneLeft, zoneRight]` 不放内容，另有越界夹紧兜底），`below` 内容 top ≥ 禁区底边。黑底伸缩用规格给的 `0.55s cubic-bezier(.32,.72,.28,1)`（主进程按真实时间轴 + 牛顿迭代求值的贝塞尔），内容 0.3s 淡入。预设（关闭 / 居中挖孔 / 偏左 / 偏右 / iPhone 灵动岛）在设置层展开成传感器列表 + 禁区 + 三个数镜像，配置页只读写那三个数即可。调试模式在小岛上画出传感器彩色圆点 + 禁区虚线框。
- **窗口动画**：以真实时间轴驱动（进度 = 已过时间 / 150 ms），Windows 定时器精度不足时表现为掉帧而不是动画变慢；重复帧与参数未变的圆角区域设置自动跳过。
- **通知接管**：探针枚举置顶通知窗口（含 ShellExperienceHost Toast 与聊天软件气泡），UI Automation 读取标题/正文；同一窗口**文本变化**也视为新通知（兼容 QQ NT 复用气泡窗口）。
- **设置文件**：`%APPDATA%\SmartCounterIsland\settings.json`（旧目录 `LiquidGlassCounter` 的设置会自动迁移）。环境变量 `SCI_USER_DATA=<目录>` 可指定替代配置目录（性能 A/B 时用，不污染真实配置）。

## 常见问题

- **小岛不出现**：看托盘图标（单击显示/隐藏）；确认「高级 → 手动模式」不是「隐藏成灵动岛」；确认「智能行为」开启；全屏状态下本来就会隐藏，退出全屏即恢复。
- **全屏时不符合预期**：看「智能行为 → 全屏授课时」选了哪种（默认完全隐藏）。判定标准是前台窗口盖住任务栏区域（桌面壁纸窗口不算全屏），**窗口最大化不算全屏**。
- **玻璃是糊的 / 不像原画**：液态玻璃模式下中心应当与原画面完全一致，只有边缘一圈折射；若整块都糊，可能被降级成了「真实模糊」，或截屏源不可用（自动回退模拟玻璃）。
- **录屏/截图里看不到小岛**：这是有意设计（`WDA_EXCLUDEFROMCAPTURE` 排除自身，避免玻璃拍到自己的重影）。
- **传感器/摄像头那一块被小岛内容挡住**：「显示效果 → 传感器避让」选一个预设（居中挖孔最常用），不对就只调「直径 / 水平偏移 / 距顶」三个数；勾上「显示传感器圆点与禁区虚线框」可以对着实物校准。小岛位置不会被改动，黑底始终把摄像头包住，内容只会走左右分栏或退到禁区下方。
- **CPU 占用偏高**：先看「高级 → 背景刷新间隔」（建议 1.0–1.6 秒），再把玻璃效果换成「模拟玻璃/关闭」；用 `--gpu` 确认没被 Chromium 降级成软件渲染。
- **通知捕获不到**：确认「智能行为 → 接管系统通知」开启；老旧聊天软件若不产生系统通知窗口则无法捕获；可用 `--demo-notify` 验证展示链路。
- **动画卡顿**：把「高级 → 动画帧率」调到 30–45，或关闭状态切换动画。
- **壁纸没换成我的图**：确认「启用壁纸功能」打开、底图来源是「我的图片文件夹」，且文件夹里有 `.jpg/.jpeg/.png/.bmp/.webp`（不递归子文件夹）。
- **壁纸不自动轮换**：确认「自动轮换」打开、频率不是「每次启动换一次」；按分钟的频率从上次更换时刻起算。
- **GPU 玻璃边缘高光太刺眼**：「高级 → 边缘高光强度」往下调（0 = 无），折射手感用「边缘折射强度 / 边缘折射范围」调。
- **大窗口 GPU 玻璃不跟手**：先用 `--gl-lag` 看是采集供不上帧还是画得慢；把「GPU 玻璃帧率」提到 60；玻璃范围很大时把「边缘折射范围 / 底部阴影」调小。
- **壁纸上的字太小 / 位置不合适**：「文字大小 / 文字位置 / 图片压暗 / 柔和底衬」逐个试。
- **想找回原来的壁纸**：「壁纸 → 恢复原壁纸」（原壁纸路径记录在 `settings.json` 的 `ui.wallpaper.original`）。
- **配置乱了想恢复默认**：删掉 `%APPDATA%\SmartCounterIsland\settings.json` 后重启（会重新生成默认事件）。
